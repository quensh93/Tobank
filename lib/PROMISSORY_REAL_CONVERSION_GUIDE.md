# راهنمای تبدیل فایل‌های promissory به نسخه آماده ساخت (Single-Import & Inline)

این سند دستورالعمل دقیقی برای تبدیل فایل‌های دایرکتوری زیر به فرمت «آماده ساخت» ارائه می‌دهد:

- منبع: `/lib/stac/tobank/flows/promissory_old/dart`
- مقصد: `/lib/stac/ready_for_build`
- مرجع الگو: `/lib/stac/ready_for_build_stable`

هدف: حفظ کامل رفتار و ظاهر صفحات، اما ساده‌سازی وابستگی‌ها به یک ایمپورت واحد و اینلاین‌کردن وابستگی‌های موردنیاز در همان فایل.

---

## اصول کلیدی

- فقط یک ایمپورت در ابتدای هر فایل وجود داشته باشد:
  ```dart
  import 'package:stac_core/stac_core.dart';
  ```
- هر وابستگی پروژه‌ای یا یوتیلیتی که از فایل‌های داخلی می‌آید (مثل `stac_common_builders.dart`) را حذف و حداقل پیاده‌سازی موردنیازش را در انتهای همان فایل اینلاین کنید.
- نام تابع صفحه (برگشتی از نوع `StacWidget`) و مقدار `@StacScreen(screenName: ...)` بدون تغییر باقی بماند.
- مسیرها، استایل‌ها، استرینگ‌ها، و متغیرهای قالب (`{{...}}`) نباید تغییر کنند.
- فایل‌ها با همان نام به دایرکتوری مقصد کپی و جایگزین شوند؛ اگر فایلی وجود ندارد، ایجاد شود.

---

## الگوی مقصد (Single-Import & Inline)

ابتدای هر فایل:
```dart
import 'package:stac_core/stac_core.dart';
```

انتهای هر فایل، دو کلاس کمکی زیر را در صورت نیاز اضافه کنید (اگر در متن صفحه استفاده شده‌اند):

```dart
// Raw JSON action helper
class StacRawJsonAction extends StacAction {
  final Map<String, dynamic> json;
  StacRawJsonAction(this.json);

  @override
  String get actionType => json['actionType'] as String;

  @override
  Map<String, dynamic> toJson() => json;
}

// Alias text style helper
class StacAliasTextStyle implements StacTextStyle {
  final String alias;
  const StacAliasTextStyle(this.alias);

  @override
  StacTextStyleType get type => StacTextStyleType.custom;

  @override
  Map<String, dynamic> toJson() => {'type': 'alias', 'value': alias};
}
```

نکته:
- فقط در صفحاتی که از این کلاس‌ها استفاده می‌کنند آن‌ها را اضافه کنید؛ در غیر این صورت نیازی به اینلاین‌کردن نیست.
- اگر کلاس کمکی دیگری از ایمپورت‌های داخلی لازم است، حداقل نسخه لازم برای برطرف‌کردن ارجاعات را مشابه همین الگو در انتهای فایل اینلاین کنید.

---

## گام‌های تبدیل برای هر فایل

1) فایل را از مسیر منبع باز کنید.  
2) تمام ایمپورت‌ها را حذف کنید و فقط ایمپورت `stac_core` را نگه دارید/اضافه کنید.  
3) کد صفحه را بدون تغییر منطقی حفظ کنید:  
   - انوتیشن `@StacScreen` و مقدار `screenName` را دست‌نخورده بگذارید.  
   - امضا و نام تابع بازگرداننده `StacWidget` را تغییر ندهید.  
4) نمادهای تعریف‌نشده ناشی از حذف ایمپورت‌ها را پیدا کنید و حداقل پیاده‌سازی موردنیازشان را در انتهای فایل اینلاین کنید.  
   - برای اکشن‌های خام ناوبری از `StacRawJsonAction` فوق استفاده کنید.  
   - برای استایل‌های مبتنی بر «علیاس» از `StacAliasTextStyle` فوق استفاده کنید.  
5) فایل تبدیل‌شده را با همان نام در مسیر مقصد ذخیره کنید و در صورت وجود، جایگزین نمایید.  
6) برای هر صفحه، یک‌بار فایل را اسکن کنید تا هیچ ارجاع حل‌نشده‌ای باقی نماند.

---

## قوانین نام‌گذاری و استقرار

- نام فایل‌ها بدون تغییر باقی می‌ماند؛ تنها محتوا به الگوی «Single-Import & Inline» تبدیل می‌شود.
- مسیر مقصد دقیقاً: `/lib/stac/ready_for_build`
- اگر در مقصد فایل هم‌نام موجود است، محتوا جایگزین شود.

---

## الزامات سازگاری

- محتوای UI، متن‌ها و مسیر دارایی‌ها تغییر نکند.  
- جهت متن‌ها (`StacTextDirection`) و استایل‌ها باید مطابق فایل منبع باقی بماند.  
- الگوی ناوبری، اعتبارسنجی‌ها و اتصالات فرم عیناً حفظ شوند.  
- فقط ساختار وابستگی‌ها ساده‌سازی می‌شود؛ رفتار صفحه تغییر نمی‌کند.

---

## اعتبارسنجی بعد از تبدیل

- پروژه را با ابزار استاندارد موجود بررسی کنید (برای نمونه، در صورت موجود بودن: `dart analyze` یا اسکریپت‌های lint/typecheck پروژه).  
- فایل‌های مقصد را یک‌به‌یک بازبینی کنید تا:  
  - بیش از یک ایمپورت وجود نداشته باشد.  
  - ارجاع حل‌نشده وجود نداشته باشد.  
  - کلاس‌های کمکی فقط در صورت نیاز اینلاین شده باشند.

---

## خطاهای رایج و راه‌حل

- خطای نماد ناشناخته پس از حذف ایمپورت‌های داخلی:  
  - حداقل پیاده‌سازی آن نماد را در انتهای فایل اینلاین کنید.  
  - ابتدا بررسی کنید آیا همان نماد در فایل‌های «ready_for_build_stable» الگوی مشابهی دارد.  
- تفاوت در متن‌ها/کلیدهای استرینگ:  
  - متن‌ها را از فایل منبع نگه دارید؛ در صورت تفاوت با نمونه‌های stable، تغییر ندهید مگر اینکه الزام محصولی دارید.  
- تکرار کلاس‌های کمکی در چند فایل:  
  - مانعی ندارد؛ اصل بر عدم استفاده از ایمپورت داخلی و استقلال هر فایل است.
